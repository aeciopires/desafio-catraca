## Observações (não bloqueantes)

- O `302` do visitante em `POST /events/{id}/purchase` usa `next=/events/{id}/purchase`. Depois do login, o navegador é levado (`303`) a `GET /events/{id}/purchase`, que responde `404`. O contrato só exige `302 /login?next=...`, por isso o item foi aprovado; seria melhor usar `next=/events/{id}` (como já faz o link "Entre para comprar").
- O cenário de C-F04-07 com o canal `partner` foi exercitado chamando o domínio direto (a API de parceiros é da F05 e não está nesta branch). O caminho HTTP real será coberto pela aresta XF-F03-F05/F05.
- A exclusão de evento cancelado da vitrine foi verificada só por simulação via SQL, porque a F07 ainda não existe.
