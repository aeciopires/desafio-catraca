## Observações (não bloqueantes)

- O pior caso medido de 202 → `confirmed` pela API foi 4042 ms (atraso agendado ≤ 3,877 s + polling do worker ≤ 200 ms + polling do cliente de 50 ms). O teto de 4000 ms deixa ~1 s de folga para o limite de 5 s do brief; o pior caso teórico é ~4,25 s (4000 + 200 + 50 ms) mais a latência das consultas.
- Com 40 amostras simultâneas não houve degradação perceptível; o worker processou os jobs no máximo 0,199 s depois do vencimento.
- O contrato cita `docker compose -p catraca ps worker`; aqui foi usado o projeto isolado `catraca-e03b` (mesmo serviço, mesma definição do Compose).
- `make gates` derruba o ambiente ao terminar; o `make down` final confirmou que nenhum contêiner do projeto ficou em execução e a porta 8093 deixou de responder.
